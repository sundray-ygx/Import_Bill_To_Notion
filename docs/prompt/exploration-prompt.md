# Exploration Phase Prompt

**生成时间**: 2026-03-02
**阶段**: Exploration - 代码库探索

## Prompt 内容

你正在为"账单导入到 Notion"项目进行代码库探索，以支持新增的"邮箱账单自动导入"功能。

### 新功能概述
在现有手动上传账单功能的基础上，新增通过邮箱自动导入账单的功能。系统需要：
- 连接到用户的邮箱账户（IMAP 协议）
- 自动检测并下载账单邮件附件
- 从邮件内容中提取账单解压密码
- 自动解压并导入账单到 Notion
- 与现有手动上传功能并存

### 你的任务

使用 **iterative-retrieval 渐进式检索模式** (DISPATCH → EVALUATE → REFINE → LOOP) 进行代码库探索：

#### Round 1: DISPATCH (初始探索)
1. **映射代码库结构**:
   - 识别项目主要目录和模块
   - 理解现有架构和设计模式
   - 标注与邮箱功能相关的关键文件

2. **识别现有模式**:
   - 认证系统如何实现
   - 文件上传和处理流程
   - Notion API 集成方式
   - 调度器实现机制
   - 多租户数据隔离机制

3. **分析相关功能**:
   - 账单解析器（parsers/）
   - 导入流程（importer.py）
   - Notion 客户端（notion_api.py）
   - 调度器（scheduler.py）
   - 用户配置管理
   - 数据库模型（models.py）

#### Round 2: EVALUATE (评估发现)
评估初始探索的结果：
- 是否找到了所有相关的代码模块？
- 是否理解了现有的数据流和架构？
- 是否识别出了可以复用的组件？

#### Round 3: REFINE (细化理解)
基于评估结果，深化探索：
- 详细分析关键模块的实现细节
- 理解模块之间的依赖关系
- 识别扩展点和集成点

#### Round 4-N: LOOP (迭代优化)
如果需要，继续迭代直到完全理解代码库。

### 重点关注领域

1. **认证与用户管理**
   - 用户登录、注册流程
   - JWT token 管理
   - 多租户数据隔离

2. **文件处理流程**
   - 文件上传机制
   - 文件解析器
   - 平台自动检测

3. **Notion 集成**
   - NotionClient 实现
   - 批量导入机制
   - 错误处理

4. **调度器系统**
   - APScheduler 使用
   - 任务配置和管理
   - 错误恢复

5. **数据库设计**
   - 现有数据模型
   - 关系定义
   - 迁移机制

### 输出要求

生成一份完整的代码库探索报告，包含：
1. **代码库结构映射**: 目录结构、模块组织
2. **关键文件标注**: 邮箱功能需要关注的文件
3. **现有模式分析**: 设计模式、架构模式
4. **数据流分析**: 现有功能的数据流
5. **集成点识别**: 邮箱功能的扩展点
6. **技术债务**: 需要注意的遗留问题
7. **实施建议**: 如何最小化侵入性地添加新功能

### 上下文信息

项目技术栈：
- 后端: Python + FastAPI
- 数据库: SQLite (SQLAlchemy ORM)
- 认证: JWT + bcrypt
- 调度: APScheduler
- Notion: notion-client SDK
