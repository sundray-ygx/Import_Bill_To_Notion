# Design Phase Prompt

**生成时间**: 2026-03-02
**阶段**: Design - 架构设计

---

## Prompt 内容

你正在为"账单导入到 Notion"项目进行架构设计，以支持新增的"邮箱账单自动导入"功能。

### 功能需求概述
在现有手动上传账单功能的基础上，新增通过邮箱自动导入账单的功能：
- 用户配置邮箱账户（IMAP 协议）
- 系统定时检查邮箱，识别账单邮件
- 自动下载附件、提取解压密码
- 解压并导入账单到 Notion
- 与现有手动上传功能并存

### 前置成果
1. **需求发现报告**:
   - 复杂度评估: 功能 6/10、技术 7/10、规模 5/10、风险 6/10
   - 开发模式: 敏捷开发 (Epic → Feature → Story)
   - 工作量: 12-16 人天（约 2-3 周）

2. **代码库探索报告**:
   - 30+ 关键文件已标注
   - 6 种核心设计模式已识别
   - 4 个主要扩展点已确定
   - 技术债务和风险已评估

### 你的任务

生成 **3 个架构方案**，并进行详细的权衡分析：

#### 方案要求

**方案一: 独立模块架构** (最小侵入)
- 邮箱功能作为独立模块
- 与现有系统松耦合
- 优先实现 MVP

**方案二: 集成扩展架构** (中等侵入)
- 深度集成到现有系统
- 复用更多现有组件
- 功能更强大

**方案三: 重构优化架构** (深度侵入)
- 统一的导入抽象层
- 支持多种导入源
- 长期最优但工作量大

#### 分析维度

使用 **模板分析维度** 进行深度架构设计：

1. **架构设计维度**
   - 整体架构风格
   - 分层设计
   - 模块划分
   - 依赖关系

2. **模块设计维度**
   - 核心模块识别
   - 模块职责划分
   - 接口设计
   - 数据流设计

3. **接口设计维度**
   - API 接口设计
   - 数据模型接口
   - 服务接口
   - 前后端交互

4. **数据库设计维度** (v3.0 database-reviewer 集成)
   - 表结构设计
   - 索引策略
   - 查询优化
   - 数据一致性
   - RLS (Row Level Security) 设计

5. **安全设计维度**
   - 凭证加密存储
   - 传输加密
   - 权限控制
   - 审计日志

6. **性能设计维度**
   - 并发处理
   - 缓存策略
   - 连接池管理
   - 批处理优化

7. **可扩展性维度**
   - 水平扩展能力
   - 垂直扩展能力
   - 新平台接入能力
   - 新功能扩展能力

8. **可测试性维度**
   - 单元测试策略
   - 集成测试策略
   - 端到端测试策略
   - Mock 和 Stub 设计

### 输出要求

生成一份完整的架构设计报告，包含：

1. **方案对比表格**
   - 3 个方案的关键特性对比
   - 优缺点分析
   - 适用场景

2. **推荐方案详细设计**
   - 架构图
   - 模块设计
   - 接口设计
   - 数据库设计（包含 database-reviewer 分析）
   - 数据流图
   - 时序图

3. **实施蓝图**
   - 开发阶段划分
   - 每阶段交付物
   - 依赖关系
   - 风险缓解措施

4. **技术选型**
   - Python 库选择
   - 理由说明

5. **数据库设计详细说明** (database-reviewer)
   - 表结构 DDL
   - 索引设计策略
   - 查询性能分析
   - RLS 策略（如需要）

### 上下文信息

现有技术栈：
- 后端: Python + FastAPI
- 数据库: SQLite (SQLAlchemy ORM)
- 认证: JWT + bcrypt
- 调度: APScheduler
- Notion: notion-client SDK

需要考虑的约束：
- 与现有功能并存
- 多租户数据隔离
- 安全性要求高（邮箱凭证）
- 调度器已有实现
